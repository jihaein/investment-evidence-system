# 급락 사건과 네이버 과거 뉴스

`events.py` → `crawl_plan.py` → `naver_crawl.py` 순서로 실행한다.
기존 사건·검색 목록 CSV가 있으면 바로 수집기를 실행할 수 있다.
수집기는 Python 표준 라이브러리와 `requests`를 사용한다.

## 현진소재 6일 파일럿

저장소 루트에서 실행한다. 기본값은 현진소재(053660), 2018-12-14~19,
우선순위 1(사건 창), 요청 사이 최소 3초다.

```powershell
.\.venv\Scripts\python.exe models/sudden/naver_crawl.py
```

같은 명령을 다시 실행하면 완료한 검색·기사는 건너뛰고 실패·미완료 건을 재시도한다.
검색이 완료됐지만 기사만 실패했을 때도 해당 기사를 다시 시도한다.
검색 요청 또는 파싱이 실패하면 다음 검색 날짜로 넘어가지 않고 종료한다.
DNS 조회를 포함한 개별 요청의 전체 대기시간은 30초로 제한한다.
기사 접속 중 시간 초과·연결 오류가 나도 추가 요청을 이어가지 않고 종료한다.
수집 실패·페이지 상한 도달이 있거나 선택한 검색을 모두 실행하지 못하면 종료 코드는 1이다.

2026-11-04 파일럿 실행 결과:

| 검색 날짜 | 검색 결과 | 네이버 본문 |
|---|---:|---:|
| 2018-12-14~16 | 0 | 0 |
| 2018-12-17 | 6 | 4 |
| 2018-12-18 | 2 | 1 |
| 2018-12-19 | 34 | 22 |
| 합계 | 42 | 27 |

19일 검색은 다음 결과 URL을 따라 4페이지를 확인했다. 외부 전용 결과는 15건,
본문 수집 실패와 입력 시각·언론사 누락은 0건이었다.
사건 `053660_20181219`의 `(2018-12-14 15:30, 2018-12-19 15:30]`에
들어오는 기사는 15건이다. 기업 관련성이나 독립적인 보도 여부는 아직 판정하지 않았다.
동일 명령 재실행 시 추가 HTTP 요청 없이 완료 기록을 재사용하는 것을 확인했다.

범위를 늘리는 예:

```powershell
.\.venv\Scripts\python.exe models/sudden/naver_crawl.py --stock 053660 --start 2018-06-17 --end 2018-12-19 --max-priority 3
```

검색 목록을 우선순위·날짜순으로 읽고 `query_alt`도 각각 검색한다.

## 전 종목 수집

`--stock`에 `all` 또는 쉼표 목록을 줄 수 있다. 여러 종목은 우선순위 → 날짜 → 종목 순으로 섞어서 돌기 때문에,
중간에 멈춰도 우선순위 1(사건 창, 19종목 1,228일)이 먼저 채워진다.

```powershell
.\.venv\Scripts\python.exe models/sudden/naver_crawl.py --stock all --start 2015-01-01 --end 2019-12-31 --max-priority 1 --out models/sudden/cache/naver_full
```

- **검색어 따옴표**: 기본으로 `"미코"`처럼 따옴표로 감싸 정확히 일치하는 기사만 찾는다.
  일반 단어 이름(미코·DMS·네이블·우전)에 관계없는 기사가 섞여 30페이지 상한에 걸리는 것을 줄인다.
  `--no-quote`는 2026-11-04 파일럿·홀드아웃 수집과 같은 방식이다.
  2026-11-04에 미코 2016-01-21·네이블 2016-05-03·DMS 2017-02-02를 두 방식으로 검색해 보니 결과가 같았다
  (네이버가 짧은 이름을 이미 단어 단위로 맞추는 것으로 보인다). 미코 검색의 '수요미식회' 기사처럼
  관계없는 결과는 따옴표로 걸러지지 않으므로 관련성 분류에서 걸러야 한다.
  따옴표는 `DMS Co`처럼 띄어쓰기가 있는 추가 검색어가 쪼개지지 않게 하는 용도로 유지한다.
  따옴표 방식이 다른 예전 기록은 재사용하지 않고 다시 검색해 덮어쓰므로,
  **전체 수집은 `--out models/sudden/cache/naver_full`처럼 별도 폴더에** 해서 파일럿·홀드아웃 DB를 보존한다.
  뒤 단계(`news_review.py`, `np_scores.py`, `validate_np.py`, `evaluate_holdout.py`)는 `--cache`로 같은 폴더를 준다.
- **추가 검색어**: `output/search_terms.csv`의 `약칭`·`영문명`·`주요_종속회사` 칸을 그 행의 `from`~`to` 기간에
  추가 검색어로 쓴다. 여러 개는 `|`로 구분한다(예: `디엠에스|DMS Co`). 칸을 채우면 그 종목의 예정 검색이 늘어나서
  `news_review.py`의 수집 완료 점검도 새 검색어까지 기다린다. `제외_접두어`는 아직 사용하지 않는다.
  관련성 분류는 아직 `stock_names.csv`의 회사명만 보므로, 영문명·종속회사로 찾은 기사는 관련 없음으로 분류될 수 있다.
- **디스크**: 응답 원문을 모두 저장한다. 남은 디스크가 `--min-free-gb`(기본 5GB)보다 적으면 다음 검색 전에 멈춘다.
- 검색 기록에는 목록상의 검색어(`query`)와 실제로 보낸 검색어(`search_query`)를 같이 남긴다.
  `summary_종목코드.json`과 `event_links_종목코드.jsonl`은 종목마다 쓴다.
`--max-pages` 기본값은 검색어·날짜당 30페이지다. 상한에 닿으면 `incomplete`로 남는다.
다음 실행에서 `--max-pages`를 늘리면 해당 검색을 첫 페이지부터 다시 수집한다.
진행 기록은 검색 단위이며, 중간 페이지부터 이어받는 방식은 아니다.

## 저장 결과

기본 위치는 Git에서 제외되는 `models/sudden/cache/naver/`다.

| 파일 | 내용 |
|---|---|
| `crawl.sqlite3` | 검색·기사별 상태와 데이터. 중복 방지·재개에 사용 |
| 해시 이름의 `.txt` | HTTP 응답 원문(HTML 또는 JSON) |
| `searches.jsonl` | 전체 검색 기록, 검색어·날짜·기사 링크·외부 전용 링크·원문 경로 |
| `articles.jsonl` | 전체 기사 기록, 제목·언론사·입력/수정/수집 시각·본문·원문 경로 |
| `event_links_종목코드.jsonl` | 이번에 선택한 검색에서 얻은 기사의 사건 창 배정 |
| `summary_종목코드.json` | 이번 검색 범위의 상태별 집계 |

검색 상태는 `complete`, `empty`, `incomplete`, `request_failed`, `parse_failed`다.
`empty`는 명시적인 검색 결과 없음 응답에서만 기록한다.
기사 상태는 `complete`, `request_failed`, `parse_failed`다.

네이버 수록 기사는 언론사 번호·기사 번호로 URL을 정규화해서 한 번 저장한다.
네이버 본문 링크가 없는 결과는 검색 기록에 `naver_url: null`로 남긴다.
개별 언론사 사이트의 본문 수집은 구현하지 않았다. 외부 전용 기사 수를 함께 보고
현재 수집본의 언론사 범위를 판단해야 한다.

## 시간 처리와 해석 범위

- 시각은 한국 시간 오프셋 `+09:00`을 포함한다. 입력 시각이 없으면 `time_unknown`이다.
- 사건 창은 최초 입력 시각 기준 `(news_window_start, news_window_end]`다.
- 판단 시각 이후 수정된 본문은 `modified_after_decision`으로 표시한다.
- `in_window`는 입력·수정 시각 기준의 배정일 뿐, 당시 본문이 복원됐다는 보장은 아니다.
  수정 시각이 표시되지 않는 경우도 있다. 현재 수집된 본문과 과거 원문을 구분해야 한다.
- 뉴스 창과 겹치는 기사만 사건 연결에 내보낸다. 시각 미상 기사는 검색 날짜와
  사건 창의 날짜가 겹치는 사건에 `time_unknown`으로 표시하므로 자동으로 근거에 포함하면 안 된다.
- 검색어 포함 여부는 기업 관련성 확정이 아니다. 아래 분류와 유사 보도 묶기, N/P는
  초기 규칙이다. LLM 연결과 최종 위험 판정은 아직 구현하지 않았다.
- 과거 검색 결과는 현재 검색 인덱스에서 얻는 결과다. 당시 모든 기사의 완전한 목록으로
  해석하면 안 된다.

## 관련성 분류와 유사 보도 묶음

```powershell
.\.venv\Scripts\python.exe models/sudden/news_review.py --drop-id 053660_20181219
```

`cache/naver/review/사건ID.json`에 사건 창·90일·180일 기준 기간의 집계를,
`사건ID_articles.jsonl`에 기사별 분류와 사유를 저장한다. 수집 중에도 실행할 수 있으며,
검색 누락·실패 또는 미수집 본문이 있으면 `ready_for_baseline_analysis`는 false다.

- `company_news`: 제목에서 회사 이름을 확인한 기업 소식 후보.
- `price_reaction`: 가격 움직임·자동 시세 기사. 급락 원인 기사로 세지 않는다.
- `roundup`: 여러 종목을 다루는 시황·공시 모음. 기업별 내용 추출 전에는 내용 분석에서 제외한다.
- `mention_review`: 본문에만 회사 이름·종목코드가 있어 추가 확인이 필요하다.
- `unrelated`: 회사 이름·종목코드를 확인하지 못했다.

2026-11-04 파일럿 시간 창의 15건은 기업 소식 4건·가격 반응 6건·종합 시황 5건이었다.
기업 소식 4건은 무한광업 서울사무소 개소의 유사 보도 1개 묶음이며 언론사는 4곳이다.
동일 보도자료 전재나 급락 원인이라는 확정 판정은 하지 않는다.

유사 묶음은 홍보·저작권 문구를 걷어낸 본문의 문자 5개 조각 집합 Jaccard 유사도 0.42,
최초 기사로부터 72시간 이내를 초기 기준으로 쓴다. 최초 기사와 직접 비교하므로
기사 간 연쇄 연결로 서로 다른 내용이 합쳐지는 것을 피한다. 기준값은 검증 대상이다.
금액·주식 수·비율이 같은 단위에서 서로 겹치지 않으면 문장이 비슷해도 합치지 않는다.
기사 수와 언론사 수를 각각 보존하며, 같은 언론사의 반복 기사는 언론사 수를 늘리지 않는다.

사건 창과 기준 기간 각각의 종료 시각 이후 수정된 본문은 분석 후보에서 제외한다.
유사 묶음도 그 시각까지의 기사로만 만들므로 나중 기사 때문에 과거의 대표 기사나
언론사 수가 바뀌지 않는다. 180일 기준 기간은 90일 기준 기간을 포함한다.
N/P의 임시 지표 계산은 아래에 설명한다. 최종 위험점수·임계값과 급락 원인 판정은 아직 없다.

기준 기간의 반복 자동 시세 본문 접속을 줄이는 선택 옵션:

```powershell
.\.venv\Scripts\python.exe models/sudden/naver_crawl.py --stock 053660 --start 2018-06-17 --end 2018-12-19 --max-priority 3 --skip-automated
```

`<코>`, `[fnRASSI]`, `[정오 시황]`, 시간대별 코스닥 시황처럼 알려진 제목 형식만
`excluded_automated` 상태로 기록하며, 공시·계약 등의 내용이 제목에 있으면 생략하지 않는다.
원 검색 HTML·링크·제목·제외 사유는 남는다. 기업 소식·모호한 제목은 본문을 수집한다.
`--skip-automated` 없이 재실행하면 생략했던 본문도 수집한다.
이 옵션을 사용한 결과에서 수집 완료는 전체 검색과 분석 대상 본문이 완료됐다는 뜻이며,
모든 기사의 본문을 받았다는 뜻은 아니다. 분류된 기존 파일럿 본문은 그대로 보존한다.

## 이전 문장 신규성 N과 보도 확산 P (lexical-v1)

```powershell
.\.venv\Scripts\python.exe models/sudden/np_scores.py --drop-id 053660_20181219 --config models/sudden/np_config_lexical.json
```

검토 JSON을 입력으로 믿지 않고 현재 수집 DB에서 시각·분류·묶음을 다시 계산한다.
출력은 `cache/naver/scores/사건ID.json`이다. 기사 링크·비교에 사용한 기준 묶음·입력 해시·
규칙 버전·설정을 함께 저장한다. 외부 접속이나 LLM 호출은 없다.

이 저장소에 N/P의 확정 산식이 없어 `np-provisional-1`이라는 임시 정의를 추가했다.
현재 기본 설정은 아래 사실 후보 방식으로 바뀌었다. 이 절의 수치는 이전 문장 방식의 결과다.
두 값은 0~1 지표이며, 악재 정도·위험점수·원인 확률이 아니다. 합산하지 않는다.

**N = 1 - 과거 180일 기업 소식과의 최대 문장 유사도**

홍보·저작권 문구를 제거한 본문의 문자 5개 조각 집합 Jaccard 유사도를 사용한다.
사건 묶음에 속한 모든 기사와 기준 기간의 모든 기업 소식 후보를 비교해 최대값을 쓴다.
과거와 같은 문장이면 0, 겹치는 조각이 없으면 1이다. 기준 문서나 사건 본문이 없으면
최대 신규성으로 처리하지 않고 유보한다. 표현이 달라지면 같은 주제여도 N이 높을 수 있어
주제·사실의 최초 공개 여부는 별도 검토가 필요하다.

**P = 같은 시간 동안 보도한 고유 언론사 수의 90일 기준 백분위**

사건 묶음의 첫 보도부터 판단 시각까지, 최대 72시간을 관찰한다. 기준 묶음도 각각 첫 보도부터
동일한 시간 길이만 관찰한다. 그 시간을 끝까지 관찰할 수 없는 기준 묶음은 제외한다.
90일 기준 시작 이전에 이미 시작된 묶음의 후속 기사도 새로운 기준 묶음으로 세지 않는다.
동일 언론사는 한 번만 센다. 값은 `(언론사 수가 작은 기준 묶음 수 + 0.5 × 동률 수) / 기준 묶음 수`다.
모든 기준 묶음과 동률이면 0.5다. 기준 묶음 또는 언론사 정보가 없거나 관찰시간이 0이면 유보한다.
기준이 72시간인데 사건은 몇 시간만 관찰하는 식으로 비교하지 않는다.

`np_config.json`에서 유사 묶음 기준·최대 관찰시간·작은 표본 경고 기준(초기값 20)을 바꿀 수 있다.
20은 지표 판정 임계값이 아니라 표본 수 경고에만 사용한다. 최대 관찰시간은 묶음의 72시간을
넘길 수 없다. 검색 또는 본문 수집이 미완료면 N/P 전체를 유보한다. 기사 시각과 사후 수정
정보는 다시 검사하고, 숫자가 나오는 지표와 유보된 지표를 구분한다.

현진소재 `053660_20181219`의 사무소 개소 묶음 결과:

| 지표 | 값 | 근거 |
|---|---:|---|
| N | 0.857301 | 180일 기사 77건과 비교. 최대 유사도 0.142699 |
| P | 0.926829 | 약 49.2시간에 언론사 4곳. 기준 묶음 41개 중 38개보다 많음, 동률 0개 |

가장 비슷한 과거 기사는 2018-11-22의 `현진소재, 무한광업과 금 유통 업무협약 체결`이다.
N이 높더라도 금광 사업 자체가 처음 알려졌다는 뜻은 아니다. P도 네이버 수록 기업 소식의
보도 범위 안에서 얻은 백분위이며 경제적 영향력이나 독립 취재 수를 뜻하지 않는다.

## 현재 기본값: 사실 후보 기반 N/P (facts-v1)

```powershell
.\.venv\Scripts\python.exe models/sudden/np_scores.py --drop-id 053660_20181219
.\.venv\Scripts\python.exe models/sudden/validate_np.py
```

`news_facts.py`가 제목의 핵심 행동을 기준으로 기업·행동·대상·상태·금액·주식 수·지분율을
추출하고 근거 문구를 함께 남긴다. 지원 범위는 CB 발행, 유상증자, 주식·지분 취득,
사무소 개소, 업무협약, 수주·공급계약이다. 업황 전망·부인·미확정·지원하지 않는 거래 변경은 추측하지 않는다.
이는 규칙으로 찾은 기사 주장 후보이며, 주장의 진위나 완전한 의미 분석 결과가 아니다.

추출 가능한 기사는 핵심 역할과 공통 세부 정보가 일치해야 같은 묶음으로 합친다.
일반 CB/영구 CB, 발행/지분 취득, 회사가 매수자인 경우/매수 대상인 경우를 구분한다.
금액·상대방·주식 수·지분율·명시된 상태가 다르면 합치지 않는다. 기사마다 같은 억원 금액을
반올림해 적었을 때는 주식 수 또는 지분율의 일치가 추가로 확인되는 경우만 허용한다.
정보가 부족해 서로 다른 두 거래에 모두 맞는 기사는 자동 배정하지 않는다.

**N은 핵심 행동·대상·상태와 비교 가능한 세부 정보의 신규 비율**이다.
180일 기준의 추출된 사실 중 같은 기업·행동·대상·상태가 없으면 새 행동 후보(N=1),
있으면 공통 세부 필드를 비교한다. 이미 보도된 핵심 사실과 세부 정보가 같으면 N=0이다.
과거 기사에 없는 필드를 바로 새로운 사실로 세지 않고 `unverified_details`에 남긴다.
이는 기사 전체의 신규성이 아니라 **추출한 핵심 사실에 한정된 임시 지표**다.
인터뷰에 새 전망 등이 추가됐더라도 그 전망을 추출하지 못하면 N에 포함하지 않는다.

본문의 금광 사업 같은 배경은 `known_context`로 분리한다. 12월 사무소 개소는 새 행동
후보지만, 금광 사업 맥락 자체는 과거에도 있었다고 함께 표시한다.
추출할 수 없는 기사는 N/P를 유보한다. 문장 비교 묶음은 검토용으로 남긴다.

P도 지원되는 사실 후보 묶음으로 기준 분포를 다시 만든다. 현재 90일 기준 묶음은
사건별 2·5·8개로 작다. `facts_min_p_baseline_groups`의 초기값 20개 미만이면
`value: null`, `status: held`로 두고 계산된 백분위는 `diagnostic_percentile`에만 남긴다.
20은 통계적으로 검증된 경계가 아니라 작은 표본을 확정값으로 쓰지 않기 위한 임시 설정이다.
이전 방식의 P와 비교 모집단이 달라졌으므로 숫자만 직접 비교해서는 안 된다.

| 사건 | 사실 후보 묶음 | 별도 검토 묶음 | 현재 처리 |
|---|---:|---:|---|
| 2018-11-05 | 3 | 1 | N 일부 계산, 전망 기사 1건 유보, P 표본 부족 유보 |
| 2018-11-21 | 2 | 0 | N 계산, P 표본 부족 유보 |
| 2018-12-19 | 1 | 0 | N 계산, P 표본 부족 유보 |

35개 사건 창 기사 중 34건은 추출 가능한 6개 사실 후보 묶음과 일치했고,
1건의 조선 업황 회복 전망은 검토 대상으로 남겼다. 440억원 유상증자 핵심 사실은
과거에 보도돼 N=0, 12월 사무소 개소는 기존 금광 사업 맥락의 새 행동 후보로 표시된다.
유사도 0.35·0.42·0.50에서 6개 사실 묶음은 같았다. 이 방식은 해당 비교에서 문장
유사도 대신 사실 일치를 쓰므로, 이것만으로 미지의 기사에 대한 정확도를 입증한 것은 아니다.

`none`이면 언론사 수를 그대로 비교한다. 기본 설정(`np_config.json`)은 기존처럼 자기 종목 90일이다.

## 3차 ACH 판정 (ach.py, 설계서 v3.1 5절)


LLM(기본 gpt-5-nano, 현재 결과는 `--model gpt-5-mini`)은 기사를 정보 단위로 나눠 인용·유형(F1~X0)·방향·사건 이름만 붙인다. 가설(H1~H5)은 지시문에 넣지 않는다.
관계표(5.4), 확실성 r_cert(표현 규칙), 2단계 병합, 가중치 w = S_sel/100 · r_src · r_cert · a_u, 판정 규칙(5.6)과
fragile·mixed·unverified_basis 플래그는 코드가 계산한다. 설계서 5.7 계산 예시는 `tests/sudden/test_ach.py`에서 재현한다.

임시 대응(설계서 입력이 아직 없음):

- S_sel = 100·V·(0.55N + 0.25P + 0.20T)에서 V는 1, N·P는 규칙+LLM 사실 기반 값(`scores_all_hybrid/pooled`). 보류된 N·P는 0.5.
- r_src 보도자료(0.8) = 6시간 안에 언론사 3곳 이상 + 대표 기사에 "밝혔다". 이슈 군집당 3개 제한은 없다.
- DART 필수 공시, 시장 규칙 K1~K4, 업종 트랙은 없다. M1은 그날 시장지수 -1.5% 이하일 때만 쓴다.
- 병합 유사도는 BGE-M3 대신 문자열 유사도(difflib). gpt-5 계열은 temperature 0을 받지 않아 기본값으로 3회 실행해 다수결.
- C1(증자·CB)은 방향을 부정으로 고정한다. 처음 실행(`ach-units-1`)에서 LLM이 유상증자·투자 유치를 긍정으로 붙여
  비가치 판정 24건 중 다수가 이것 때문이었다(`cache/naver_full/ach_summary_units1.json`).

## 사후 주가 검증 (backtest.py, 설계서 7절)


AR은 시장모형(D-120~D-1 회귀 α·β)이고 CAR(1,k)는 D+1~D+k AR 합, 회복률은 CAR / |AR_D|다. 그룹 차이(비가치 - 가치훼손)는
급락일 군집 표준오차 t와 같은 날 사건을 한 블록으로 섞는 순열검정 p로 본다. 주가는 2019-12-30까지라 늦은 사건은 긴 구간에서 빠진다.
결과는 `<ach 폴더>/backtest.json`, 사건별 값은 `backtest.csv`다.

2026-11-09 결과 (평균 CAR, 괄호는 사건 수):

| 판정 | mini v3 CAR(1,20) | mini v3 CAR(1,60) | nano v2 CAR(1,20) | nano v2 CAR(1,60) |
|---|---:|---:|---:|---:|
| 가치훼손 | -2.6% (35) | -11.4% (33) | -1.4% (47) | -8.7% (46) |
| 비가치 | -3.8% (35) | -11.6% (32) | -3.7% (15) | -12.9% (15) |
| 판단보류 | -0.5% (139) | -3.4% (135) | -1.2% (147) | -4.4% (139) |
| 차이 t / 순열 p | -0.28 / 0.78 | -0.03 / 0.97 | -0.52 / 0.61 | -0.56 / 0.63 |

- 설계서가 기대한 방향(비가치가 더 회복)이 나오지 않았다. 두 모델 모두 차이가 0에 가깝고 유의하지 않다.
  fragile 판정을 빼도 같다(mini CAR(1,60) 차이 -5.3%p, p=0.62).
- 판정이 난 사건(가치훼손·비가치)은 둘 다 60일 동안 약 11% 더 빠졌다. 판단보류(대부분 기업 소식 없음)는 -3.4%다.

  감사의견 비적정·관리종목 C2, 횡령·배임·경영권 분쟁 C3, 소송 F5, 해명 R2). 가중치는 등급값(사건성 1.0)이다.

### 판정 설정 튜닝 (tune.py, 2026-11-10, 튜닝용 134건만)


저장된 ACH 단위를 설정만 바꿔 다시 판정하고 같은 사건의 사후 CAR와 비교한다(LLM 재호출 없음). 격자는 미리 정한

- `market_only_holds`: 시장 규칙(K4) 단위만 있는 사건은 판단보류
- `positive_weight`: 좋은 소식(긍정 방향) 단위 가중 배수 1.0 / 0.5 / 0.0

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 아니오 | 1.0 | 0.5 (설계서) | 8 | 55 | 71 | 23 | -7.8%p | 0.43 |
| 예 | 1.0 | 0.5 | 8 | 39 | 87 | 7 | -5.9%p | 0.53 |
| 아니오 | 0.0 | 0.5 | 18 | 28 | 88 | 23 | -7.0%p | 0.42 |
| 예 | 0.0 | 0.7 | 19 | 10 | 105 | 6 | -13.6%p | 0.26 |

(전체 18개는 tuning_log.json. 차이는 18개 모두 음수였다: -4.2%p ~ -13.6%p, 순열 p 0.26~0.63.)

- 어떤 설정에서도 "비가치가 더 회복한다"는 방향이 나오지 않았다. 이 세 가지 손잡이로는 판정이 사후 수익률과 맞춰지지 않는다.
- 결과를 보고 고르면 과적합이므로, 설정은 근거로 정한다. `market_only_holds=True`는 근거가 시장 규칙 하나뿐인 판정을
  막아 fragile을 23 → 7로 줄인다(K 단위는 설계서상 간접 증거). 나머지(positive_weight 1.0, gap 0.5)는 설계서 값을 유지한다.

새 기사를 받기 전에 `news_facts.py`, `news_review.py`, `np_scores.py`, `np_config.json`의
SHA-256을 `cache/naver/holdout/plan_v1.json`에 저장했다. 이번 비교에서는 이 규칙을 바꾸지 않았다.
내용을 읽고 예측을 실행하기 전에 `annotations_v1.json`에 핵심 사실·역할·금액·같은 소식의
그룹을 기록했다. 라벨은 보조 모델의 내용 검토이며 별도 사람 검수나 독립 정답 데이터가 아니다.

사건 창 11일의 검색을 모두 마쳤고, 자동 시세 본문 생략과 시간 경계·사후 수정 제외 후
본문 17건을 검토했다. 180일 기준 기간은 받지 않았으므로 이 단계에서는 N/P를 계산하지 않는다.

| 사건 | 검토 본문 | 핵심 사실이 있는 기사 | 맞게 추출한 기사 | 사실 추출 유보 |
|---|---:|---:|---:|---:|
| 대창솔루션 2018-05-25 | 14 | 11 | 0 | 11 |
| 대한광통신 2018-02-28 | 3 | 1 | 1 | 0 |

대한광통신의 805억원 유상증자는 총액·행동·기업을 맞게 추출했다. 대창솔루션의 11건은
한산과 캐나다 원전 핵폐기물 컨테이너 공급계약 보도인데, 현재 규칙에 수주·공급계약이 없어
모두 유보했다. 처리 범위는 12건 중 1건(약 8.3%)이다. 추출된 1건에 오류가 없다는 것만으로
정확도가 높다고 해석하면 안 된다. 비교 가능한 같은 계약 기사 55쌍도 모두 묶음 판정을
유보했으므로 재현율을 성공으로 세지 않는다.

출력은 `holdout/evaluation_v1.json`이며 기사별 예측·유보 사유와 검토 라벨 차이를 남긴다.
규칙 해시가 달라지거나 본문 해시와 라벨이 맞지 않으면 평가를 중단한다. 평가 명령의 종료
코드 0은 비교 절차가 완료됐다는 뜻이며 규칙의 정확도가 합격했다는 뜻이 아니다.
다음 규칙 보완은 수주·공급계약 지원이다. 이 자료로 규칙을 수정하면 해당 기사는 회귀
사례로 전환하고, 수정 후 정확도는 다른 새 기사로 다시 확인해야 한다.

## 수주·공급계약 보완 (news-facts-2)

수주·공급·납품 제목은 본문에서 계약임을 확인한 뒤 공급물, 계약 상대방, 원화 금액,
공급지역, 명시된 계약 시작·종료일을 추출한다. 발주처가 본문에 없으면 최종 수요자나
일반 명사를 대신 넣지 않는다. 금액은 계약금액 항목을 우선해 매출액·시장 규모와 구분한다.
현재 외화·미확인 계약·기간 변경·금액 정정은 유보한다.

핵폐기물 컨테이너/처리용기/저장용기는 명시된 동의어로 정규화한다. 다른 공급물은
제목 또는 계약명에서 표기를 정리하되, 일반적인 '장비'처럼 특정하기 어려우면 유보한다.
다른 발주처·다른 기간·다른 공급물·충돌하는 금액은 합치지 않는다.

91억원, 91.1억원, 91억773만원처럼 보도 금액의 자릿수가 다른 경우는 각 기사의 원래 수치를
보존한다. 표시 정밀도에 따른 구간이 겹치고 계약 상대방/종료일 또는 같은 날의 공급물·지역이
추가로 맞는 경우에만 동일 계약 후보로 묶는다. 이는 실제 금액의 반올림이 증명됐다는 뜻은 아니다.
그룹의 기준 사실에는 가장 상세한 금액의 보도와 원문 URL을 연결하고, 첫 보도 시각은 유지한다.

기존 검토 17건에 대한 회귀 확인:

| 항목 | 이전 동결 규칙 | 보완 후 회귀 결과 |
|---|---:|---:|
| 핵심 사실 12건 중 맞게 추출 | 1 | 12 |
| 대창솔루션 공급계약 11건 | 모두 유보 | 1개 계약 후보 묶음 |
| 같은 계약 기사 55쌍 | 모두 유보 | 55쌍 연결, 잘못된 병합·분할 0 |

상세 금액은 91억773만원, 상대방은 한산, 공급지는 캐나다이며 계약 기간은
2018-05-25~2019-12-31이다. 일부 기사에 없는 상대방·기간은 다른 기사 값으로 채우지 않았다.
이 표는 이미 내용을 검토하고 규칙 보완에 사용한 사례의 회귀 결과로, 새 기사 정확도 100%를
뜻하지 않는다. 별도 사람 검수 전 보조 라벨이라는 한계도 유지한다.

```powershell
.\.venv\Scripts\python.exe models/sudden/evaluate_holdout.py --regression --annotations models/sudden/cache/naver/holdout/annotations_regression_v2.json
```

이전 결과는 `holdout/frozen_v1/`에 보존했다. 원래 `evaluation_v1.json`도 그대로 유지한다.
규칙이 바뀐 뒤 기본 평가 명령을 실행하면 기존 결과를 덮어쓰지 않고 `evaluation_attempt_v1.json`에
변경을 기록한다. 명시적인 `--regression` 실행만 `regression_news-facts-2.json`에 새 결과를 저장한다.
라벨에는 상대방·기간이 있어야 하는 필드뿐 아니라 없어야 하는 필드도 기록해 추측 채우기를 검사한다.

이 단계의 사실 추출 규칙은 `news-facts-2`, N/P 규칙은 `np-facts-provisional-2`다.
이전 사실 방식의 점수는 `cache/naver/facts_v1/`에 보존했다. 새 종목 두 건은 180일 기준 기간을
수집하지 않았으므로 이번에도 N/P를 계산하지 않는다.

## 보완 규칙을 동결한 새 계약 기사 검토

`news-facts-2` 등 네 규칙 파일을 수정하지 않고 진성티이씨 2017-12-05와 대한광통신
2018-01-05의 하루치 기사를 새로 수집했다. 검색 전에 종목·기간·선정 방식을
`holdout/sampling_v2.json`에 기록하고, 확인된 계약 보도 날짜와 기존 기사 URL 목록을
`plan_v2.json`에 저장했다. 기존 검토 기사와 겹치는 URL은 없다. 급락 사건 표본이 아닌
공급계약 유형 확인용 편의 표본이며, N/P와 수익률 예측력은 평가하지 않았다.

본문을 읽고 예측 실행 전에 `annotations_v2.json`에 검토 라벨과 허용 표기를 기록했다.
이 라벨은 별도 사람 검수 전의 보조 평가다. 여러 계약을 보도한 기사는 한 계약으로
축약하면 오류로 처리하고, 단일 계약 기사끼리의 묶음 비교에서는 제외한다.

| 날짜·종목 | 검토 본문 | 핵심 사실 기사 | 모든 검토 필드 일치 | 추출 유보 | 필드·계약 분리 오류 |
|---|---:|---:|---:|---:|---:|
| 진성티이씨 2017-12-05 | 12 | 10 | 0 | 1 | 9 |
| 대한광통신 2018-01-05 | 9 | 7 | 0 | 0 | 7 |
| 합계 | 21 | 17 | 0 | 1 | 16 |

0건 일치는 개별 필드가 전부 틀렸다는 뜻이 아니다. 예를 들어 진성티이씨 계약금액은
10건 중 7건이 맞고 1건은 추출 유보였지만, 계약 상대·공급물·공급지역 등 다른 필드에서
오류가 있어 완전 일치 기사는 없었다. 결과의 `field_checks_single_fact_articles`에서
필드별 일치·누락·추출 유보를 따로 확인할 수 있다.

주요 실패는 복합 금액(`3천731억원`, `3731억887만4433원`), 영문 법인명,
상대방 소재 국가와 공급지역의 혼동, 제목 접두어가 섞인 공급물이다. 대한광통신 기사
5건은 두 계약을 한 사실로 추출했다. 진성티이씨의 같은 계약 기사 45쌍 중 3쌍만
연결됐고, 33쌍은 잘못 분리됐으며 9쌍은 유보됐다. 이 표본에서 묶음 재현율은 약 6.7%다.

```powershell
.\.venv\Scripts\python.exe models/sudden/evaluate_holdout.py --plan models/sudden/cache/naver/holdout/plan_v2.json --annotations models/sudden/cache/naver/holdout/annotations_v2.json --out models/sudden/cache/naver/holdout/evaluation_v2.json
```

수집한 네이버 본문 21건에 대한 결과는 `holdout/evaluation_v2.json`에 보존한다.
외부 언론사 링크만 있는 검색 결과 14건은 본문 평가에 포함하지 않았다. 두 날짜의
검색·네이버 본문 수집 완료는 전체 언론사 기사 확보를 뜻하지 않는다.
이번에는 오류를 관찰한 뒤 추출 규칙을 고치지 않았다. 다음 보완 대상은 금액 파싱,
법인명과 역할 구분, 여러 계약의 분리이며, 보완에 사용하면 이 기사도 회귀 사례가 된다.

## 복합 계약금액 보완 (news-facts-3)

새 표본 검토 이후 첫 보완으로 원화 금액의 전체 범위를 읽도록 바꿨다.
`3천731억원`을 731억원으로, `3731억887만4433원`을 4433원으로 잘라 읽던 오류를
수정했다. 조·억·만·원 및 천·백·십 단위를 처리하고 원문 금액 근거를 그대로 남긴다.
표시 정밀도도 마지막 원 단위까지 반영해 서로 다른 세부 금액을 같은 계약으로 합치지 않는다.

원래 동결 평가·라벨·규칙은 `holdout/frozen_v2/`에 보존했고 `evaluation_v2.json`도
유지했다. 이번 보완에 사용했으므로 해당 21건은 이후 `news-facts-3`의 회귀 사례다.

| 단일 계약 기사 12건의 금액 | news-facts-2 동결 결과 | news-facts-3 회귀 결과 |
|---|---:|---:|
| 검토 금액 일치 | 9 | 11 |
| 잘못 읽은 금액 | 2 | 0 |
| 사실 추출 유보 | 1 | 1 |

다른 필드와 여러 계약 분리 오류는 이번에 수정하지 않았다. 핵심 사실 기사 17건 중
모든 검토 항목 일치는 여전히 0건이며, 위 표는 전체 사실 추출 정확도가 아니다.
새 결과는 `holdout/regression_news-facts-3_contract_sample.json`에 별도로 저장한다.

```powershell
.\.venv\Scripts\python.exe models/sudden/evaluate_holdout.py --regression --plan models/sudden/cache/naver/holdout/plan_v2.json --annotations models/sudden/cache/naver/holdout/annotations_v2.json --out models/sudden/cache/naver/holdout/regression_news-facts-3_contract_sample.json
```

이 단계의 사실 추출 규칙은 `news-facts-3`다. 기존 N/P 출력은 이전 규칙으로 생성된 결과이므로
이번 금액 보완의 N/P 검증 결과로 해석하지 않는다. 다음 구현 대상은 영문 계약 상대방과
공급지역의 역할 구분, 여러 계약의 분리다. 새 기사 일반화 검증은 이 보완을 마친 뒤 필요하다.

## 계약 상대방·공급지역 보완 (news-facts-4)

계약 상대방 항목은 다음 항목이나 문장 경계까지 읽어 영문 법인명의 공백·마침표·쉼표를
보존한다. 본문의 `기업명(영문명)와 … 공급계약`도 인식하며, 국가명 자체를 상대방으로
채우지 않는다. 공급지역은 명시된 공급지역 항목이나 공급·납품 목적지 문맥에서 추출한다.
기사에 처음 등장한 국가를 채우던 처리를 제거해 상대 기업의 본사 소재국과 구분했다.
지역 목록의 여러 목적지와 원문 근거를 보존하며, 지역명이 다음 문장의 공급 표현과
잘못 연결되지 않도록 검사한다.

같은 21건에 대한 회귀 비교는 다음과 같다. 단일 계약 기사만 필드별 비교에 포함한다.

| 항목 | news-facts-3 | news-facts-4 |
|---|---:|---:|
| 계약 상대방 일치 / 검토 12건 | 1 | 10 |
| 공급지역 일치 / 검토 11건 | 2 | 10 |
| 핵심 사실 기사 17건 중 모든 항목 일치 | 0 | 5 |
| 사실 추출 유보 | 1 | 2 |
| 필드·계약 분리 오류 기사 | 16 | 10 |

추출 유보가 늘어난 1건은 제목에 공급물이 없는 기사다. 잘못 붙인 상대방 국가가
공급물로 남던 문제가 사라지면서 공급물 확인 불가로 처리된다. 공급물의 제목 접두어·잔여
금액·`의 건` 제거와 여러 계약의 분리는 아직 보완하지 않았다. 따라서 이 결과는 전체
추출 완성이나 새 기사 일반화 정확도를 뜻하지 않는다.

이전 규칙과 회귀 결과는 `holdout/frozen_v3/`에, 새 결과는
`holdout/regression_news-facts-4_contract_sample.json`에 저장했다. 원래 동결 결과와 라벨은
수정하지 않았다. 이 단계의 사실 추출 규칙은 `news-facts-4`이며 기존 N/P 출력은 재생성하지 않았다.

```powershell
.\.venv\Scripts\python.exe models/sudden/evaluate_holdout.py --regression --plan models/sudden/cache/naver/holdout/plan_v2.json --annotations models/sudden/cache/naver/holdout/annotations_v2.json --out models/sudden/cache/naver/holdout/regression_news-facts-4_contract_sample.json
```

## 공급물·여러 계약 보완 (news-facts-5)

공급물은 계약명과 본문에 명시된 표현을 우선하고 복합 금액, 지역 수식어, 공시의
`체결의 건`을 제거한다. 제목에 공급물이 없더라도 본문에 명시돼 있으면 사용한다.
기업별 동의어를 추가해 서로 다른 상세 공급물을 강제로 같은 이름으로 바꾸지는 않았다.

여러 공급계약을 각각의 상대방·금액과 연결된 문장으로 나눌 수 있을 때만 분리한다.
계약 건수와 분리 건수가 다르거나 한 문단에 여러 금액이 섞여 있으면 전체를 유보한다.
합계 금액이나 `각각` 표현만 보고 대응 관계를 추측하지 않는다. 각 계약은 원문 발췌를
보존하며, 하나의 기사의 `primary`에 총액을 넣는 대신 `facts` 목록으로 제공한다.
호환 함수 `fact_list()`는 단일·복수 추출을 모두 목록으로 반환한다.

묶음 구성원은 원문 URL과 `fact_index`로 구분한다. 그룹 기준 사실에도 원문 URL·계약
인덱스를 남기며 기사 수·언론사 수는 중복 집계하지 않는다. N은 그룹의 해당 계약과
과거 기사의 각 계약을 비교한다. 민감도 비교도 URL만이 아닌 계약 인덱스를 사용한다.
N/P의 지원 기사 수에는 여러 계약 기사도 포함하되, 기준 기사 수와 사실 수는 구분한다.

원래 동결 라벨은 유지하고, 계약별 금액·상대·지역·명시된 종료일을 내용에 따라 검토한
`annotations_regression_v5.json`을 별도로 작성했다. 평가기는 계약 순서에 관계없이
계약 수와 각 계약의 검토 필드를 함께 확인한다. 금액과 상대방이 서로 바뀌면 오류다.
이 라벨은 이미 본 기사의 보조 회귀 라벨이며 독립 정답 데이터가 아니다.

| 모든 검토 항목 일치 | 5 | 13 |
| 추출 유보 | 2 | 4 |
| 검토 필드·계약 분리 오류 | 10 | 0 |

21건 중 핵심 사실 기사 17건에 대한 결과다. 단일 계약 12건 중 11건이 검토 필드와
일치하고 제목에 행동이 없는 1건은 유보했다. 여러 계약 기사 5건 중 2건은 두 계약으로
분리해 일치했으며, 나머지 3건은 안전한 분리 불가로 유보했다. 원래 다중 계약 라벨에는
개별 계약 필드가 없었으므로 이전 표와의 비교는 라벨 확장을 포함한다.

필드 추출과 기사 묶음 정확도는 별개다. 진성티이씨의 같은 계약 45쌍 중 연결은 6쌍,
잘못 분리는 30쌍, 유보는 9쌍으로 묶음 재현율은 약 13.3%다. 공급물의 상세 표현과
법인명·지역 표기 차이가 남아 있어 새 기사 검증과 동일 계약 묶음 개선이 필요하다.

## 이름 없는 계약 상대방 제외 (news-facts-8)

계약 상대방의 명시 항목과 본문 표현 모두에서 `업체`·`회사`·`발주사` 같은 일반 역할,

명시 항목이 비공개이면 본문의 다른 회사로 대체하지 않는다. 접미사가 `회사`라는 이유만으로
실제 이름을 제외하지 않으며, `미래회사`·`중국중차`·영문 법인명은 보존한다.

구체적인 상대방이 없어도 계약 금액과 명시된 계약 종료일 등 다른 확인 근거가 있으면
해당 사실 후보는 유지하되 상대방 필드와 근거는 비워 둔다. 기존 테스트의 가상 상대방도
일반 역할명 `발주사` 대신 구체적인 가상 이름으로 바꿨다.

v3 표본의 핵심 사실 기사 17건에서 모든 검토 항목 일치는 10건에서 12건으로 늘었다.
필드 오류는 3건에서 1건으로 줄었고 유보는 4건으로 유지됐다. 남은 필드 오류는 제목의
중국 공급 목적지 누락이다. 연간 누적 계약 건수의 복수 계약 오인 등 기존 유보 사유는
이번에 수정하지 않았다.

관련 테스트 225개가 통과했고, 접속 없는 회귀 결과 재현과 이전 평가·라벨 보존을 확인했다.
이전 규칙·회귀 결과는 `holdout/frozen_v7/`, 새 결과는
`holdout/regression_news-facts-8_contract_sample_v3.json`에 저장했다. 현재 사실 규칙은
`news-facts-8`이며 이 결과는 보완에 사용한 기사의 회귀 결과다. 기존 N/P 출력은 유지했다.
